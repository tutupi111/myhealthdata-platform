# v0.3 AI 配置后台 · 设置说明

v0.3 为后续「医疗资料 AI 自动解析」建立后台可配置的 AI 引擎层。本阶段仅实现配置与数据结构，不实现真实 AI 调用。

---

## 一、新增数据库表（Supabase）

在 Supabase SQL Editor 中执行：`docs/supabase-v0.3-ai-tables.sql`

### 1. ai_models

| 字段 | 类型 | 说明 |
|------|------|------|
| id | uuid | 主键 |
| provider | varchar(50) | 提供商标识，如 openai、azure |
| model_name | varchar(100) | 模型名称，如 gpt-4o |
| base_url | varchar(255) | API 基础 URL，可选 |
| api_key | varchar(255) | API Key，可选 |
| supports_vision | boolean | 是否支持图像输入 |
| supports_json | boolean | 是否支持 JSON 输出 |
| is_default | boolean | 是否默认模型 |
| is_active | boolean | 是否启用 |
| priority | int | 优先级，数值越小越优先 |
| notes | text | 备注 |
| created_at | timestamptz | 创建时间 |

### 2. ai_task_configs

| 字段 | 类型 | 说明 |
|------|------|------|
| id | uuid | 主键 |
| task_type | varchar(50) | 任务类型，唯一 |
| preferred_model_id | uuid | 首选模型，FK ai_models(id) |
| fallback_model_id | uuid | 备用模型，FK ai_models(id) |
| prompt_template | text | 提示词模板 |
| timeout | int | 超时（秒） |
| max_tokens | int | 最大 token 数 |
| is_enabled | boolean | 是否启用 |
| created_at / updated_at | timestamptz | 创建/更新时间 |

### 3. ai_logs

| 字段 | 类型 | 说明 |
|------|------|------|
| id | uuid | 主键 |
| record_id | uuid | 关联健康记录 ID |
| task_type | varchar(50) | 任务类型 |
| model_name | varchar(100) | 使用的模型名 |
| status | varchar(20) | success / failed / pending |
| error_message | text | 失败时的错误信息 |
| duration_ms | int | 耗时（毫秒） |
| created_at | timestamptz | 创建时间 |

执行 SQL 后会自动插入 5 条默认任务配置：`ocr_extract`、`doc_classify`、`structured_extract`、`tagging`、`summary`。

## 二、新增管理后台页面

| 路径 | 说明 |
|------|------|
| /admin/ai-models | AI 模型列表、新增、编辑、启用/禁用、设为默认 |
| /admin/ai-tasks | 按任务类型配置首选/备用模型、prompt、timeout、max_tokens |
| /admin/ai-logs | AI 执行日志列表，支持按状态与任务类型筛选 |

侧栏入口：管理后台 → 「AI 模型」「AI 任务」「AI 日志」。

---

## 三、如何添加一个模型

1. 登录管理后台，进入 **AI 模型**（/admin/ai-models）。
2. 点击 **新增模型**，在右侧 Sheet 中填写：
   - **Provider**：如 `openai`、`azure`、`local`。
   - **模型名称**：如 `gpt-4o`、`gpt-4o-mini`。
   - **Base URL**（可选）：自建或代理时填写。
   - **API Key**（可选）：密钥，编辑时留空表示不修改。
   - **支持视觉 / 支持 JSON**：按模型能力勾选。
   - **默认模型**：勾选后会将其他模型的「默认」取消。
   - **启用**：不勾选则不会在任务路由中被选用。
   - **优先级**：数字越小越优先（多模型时排序用）。
   - **备注**：可选说明。
3. 点击 **保存**。列表中出现新模型后，可在 **AI 任务** 中将其选为首选或备用模型。

---

## 四、如何配置任务路由

1. 进入 **AI 任务**（/admin/ai-tasks）。
2. 表格中会列出 5 种固定任务类型：OCR 识别、文档分类、结构化抽取、标签生成、摘要生成。
3. 点击某一行的 **编辑**，在右侧 Sheet 中：
   - **首选模型**：该任务优先使用的模型（从已启用的 AI 模型中选择）。
   - **备用模型**：首选失败或不可用时使用的模型（可选）。
   - **Prompt 模板**：可选，支持占位符如 `{{extracted_text}}`、`{{doc_type}}`，后续 AI 引擎替换后发给模型。
   - **超时（秒）** / **Max Tokens**：请求参数。
   - **启用该任务**：不勾选则该任务类型不会被执行。
4. 点击 **保存**。配置立即生效，后续接入 AI 解析时会按此路由调用对应模型。

## 五、API 接口（供前端调用）

- `GET /api/admin/ai-models`：模型列表  
- `POST /api/admin/ai-models`：新增模型  
- `GET /api/admin/ai-models/[id]`：单条模型  
- `PATCH /api/admin/ai-models/[id]`：更新模型  
- `DELETE /api/admin/ai-models/[id]`：删除模型  
- `GET /api/admin/ai-task-configs`：任务配置列表（含关联模型名）  
- `GET /api/admin/ai-task-configs/[id]`：单条配置  
- `PATCH /api/admin/ai-task-configs/[id]`：更新配置  
- `GET /api/admin/ai-logs?limit=50&offset=0&status=&task_type=`：日志列表（分页、筛选）

---

## 六、注意事项

- 本阶段**不调用真实 AI**，仅维护配置与日志表结构；后续 v0.4+ 接入解析时再读取 `ai_task_configs` 与 `ai_models` 执行调用，并写入 `ai_logs`。
- `api_key` 仅保存在库中，列表接口不返回明文；编辑时若不想修改密钥可留空 API Key 字段。
- 若未执行建表 SQL，**AI 任务** 列表会为空，需先执行 `docs/supabase-v0.3-ai-tables.sql`。
